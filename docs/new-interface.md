## 0. 两个接口的职责

| 接口                 | 承担                                                | 数据来源                                                         |
| -------------------- | --------------------------------------------------- | ---------------------------------------------------------------- |
| `POST /upload/ppi`   | **睡眠详情**（逐秒分期曲线）+ 心率/血氧/PPI         | 设备每秒一条：广播 `0x50` 1 Hz + 生命体征历史 `0x3A/0x3B` 补缺秒 |
| `POST /upload/sleep` | **睡眠摘要**（入睡/醒来时刻 + 三段时长 + 静息心率） | 设备睡眠事件 `0x3C/0x3D` 的 `SleepResult`，一晚一条              |

睡眠详情不再由睡眠接口提供：设备事件里只有 `2 个时刻 + 3 个时长`，画不出逐秒曲线；
曲线只能来自设备每秒的 `status`。

## 1. `/upload/ppi`

```json
{
	"device": "BOOM-0001",
	"address": "AA:BB:CC:DD:EE:FF",
	"timezone": "08:00",
	"datas": [{ "time": "2026-10-08 02:13:07", "hr": 62, "spo2": 950, "ppi": 980, "activity": 1 }]
}
```

| 字段       | 说明                                                                             |
| ---------- | -------------------------------------------------------------------------------- |
| `time`     | 该秒时间，按 `timezone` 格式化。秒值本身来自设备（广播 `utc` / 历史 `startSec`） |
| `hr`       | 心率 bpm，设备原始值                                                             |
| `spo2`     | 血氧，**设备原始值（×10）**：`950` = 95.0%。⚠️ 口径已改，见 §3.1                 |
| `ppi`      | 脉波间期 ms，设备原始值                                                          |
| `activity` | 设备 `status` 的低 3 位，**睡眠详情就是它**，见下表。                            |

`activity` 编码：

| 值    | 含义                | 属于睡眠 |
| ----- | ------------------- | -------- |
| 0     | 深度睡眠            | 是       |
| 1     | 浅度睡眠            | 是       |
| 2     | 其他睡眠            | 是       |
| 3     | 精神放松            | 否       |
| 4 / 5 | 活动量低 / 活动量高 | 否       |
| 6 / 7 | 精神兴奋 / 身体压力 | 否       |

## 2. `/upload/sleep`

```json
{
	"device": "BOOM-0001",
	"address": "AA:BB:CC:DD:EE:FF",
	"timezone": "08:00",
	"datas": [
		{
			"time": "2026-10-08 07:30:00",
			"sleepOnsetTime": 25200,
			"awakeTime": 1800,
			"lightSleepPeriod": 14400,
			"deepSleepPeriod": 7200,
			"otherSleepPeriod": 1800,
			"heartRateRest": 55
		}
	]
}
```

| 字段                                                        | 说明                                                 |
| ----------------------------------------------------------- | ---------------------------------------------------- |
| `time`                                                      | 事件结算时刻（设备时钟），按 `timezone` 格式化       |
| `sleepOnsetTime`                                            | 入睡时刻，**距 `time` 的秒数**（设备原样给的相对值） |
| `awakeTime`                                                 | 醒来时刻，**距 `time` 的秒数**                       |
| `lightSleepPeriod` / `deepSleepPeriod` / `otherSleepPeriod` | 浅睡 / 深睡 / 其他睡眠时长，秒                       |
| `heartRateRest`                                             | 静息心率 bpm                                         |

## 3. 本次调整

### 3.1 `spo2` 的口径变了

|                  | 老接口（线上现状）                     | 新接口                                             |
| ---------------- | -------------------------------------- | -------------------------------------------------- |
| App **落库**的值 | `95`（先把设备的 `950` 除以 10 再存）  | `950`（设备原始值，原样入 `ppi_data.spo2`）        |
| App **上传**的值 | `95`（百分数）                         | `950`（设备原始值，×10）                           |
| App 做了什么     | 落库前 `/10`，上传时用的就是折算后的值 | 落库、上传都用原始值；只有界面展示时才折算成百分比 |

**`spo2 = 0` 的含义是「这一秒设备没给血氧」，不是 0%。**

原因在设备侧：逐秒生命体征历史 `VitalData_Per_Second`（协议 2.1.3）里**根本没有 spo2 字段**，
只有心率 / 状态 / 步频 / 加速度 / PPI；带 spo2 的只有每秒广播 `custom_adv_data_t`（协议 2.1.2）。
所以一个睡眠窗口里被历史补回来的秒，spo2 一律是 `0`；只有实时收着广播的那部分秒才有真实值。
